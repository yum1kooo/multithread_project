<h1>Многопоточный Магазин</h1>

<h2>Shop (Main)</h2>

<h4>Имитирует работу высоконагруженной системы заказов. Управляет инициализацией сервисов и запуском потоков (покупателей и администраторов).

Через serviceLogic.firtsInit(bank, delivery) инициализируем наши экземпляры класса

</h4>
<h2>Delivery</h2>

<h4>getInstance() — возвращает экземпляр класса </h4>

<h4>generateNewOrders() — Producer.</h4>Генерирует новый заказ и кладет в очередь, если очередь полна (15 элементов) — уходит в wait(). Создаем user для имитации работы как будто пользователи заходят в очередь. 
Далее создаем переменную boolean для того что бы отслеживать размер очереди тк offer возвращает true если место есть(соответсвенно добавляем в очередь) И false если добавить не получилось то очередь полна


<h4>processingOrders(int orderCoast) — Consumer.</h4> User user = queue.poll() - с помощью него берем 1 пользователя из очереди, далее забирает заказ из очереди.Проверяет баланс пользователя. Если средств достаточно — одобряет заказ.

<h4>getSizeQueue() — возвращает текущее количество заказов в очереди. </h4>

<h4>INSTANCE_BANK — единственный экземпляр класса.</h4>

<h4>getInstance() — возвращает экземпляр класса (синхронизация по Bank.class)</h4>

<h4>getPaymentById(int id) — заглушка, возвращает случайный boolean (прошла оплата или нет).</h4>

countOrder, orderCoast — параметры конфигурации.

Основные методы:
firtsInit(Bank bank, Delivery delivery) — имитирует "тяжелую" загрузку сервисов с задержками. Запрашивает ввод данных через консоль (Scanner). Использует latch.countDown().
</h4>
